# 归零记账助手（Android）

面向个人归零账本的通知采集助手，目标设备为小米14。原生 Android / Java，最低 Android 8.0。源码中不包含任何个人账号、账本、API Key或签名私钥。

## 当前功能

- 微信和支付宝标题未命中预设名单时，若含明确付款信息，先保存到待确认，禁止自动提交。含付款描述的聊天也可能进入待确认，需要核对是否为真实消费；普通聊天和推广仍过滤。
- 支持“已支付¥10.20”等不带“元”的通知金额；旧待确认记录金额为空时，打开确认框会重新解析原文并预填。合并通知可能包含多笔，仍需人工逐笔核对。
- 在“记录”中，已忽略通知可恢复到待确认。恢复不会自动提交；退款、日报和合并通知需先核对是否是真实的单笔消费。
- 退款通知和记账日报直接在采集阶段过滤，不产生新的消费待确认记录；旧的已忽略退款/日报也没有恢复入口。
- 通知服务断开时会请求系统重连；设置页可手动点击“尝试重连通知服务”。若系统持续显示未连接，可在通知使用权设置中关闭再开启。
- 通知服务连接时自动补查通知栏仍保留的微信/支付宝通知；设置页也可点击“补查通知栏现存通知”。最多检查100条目标通知，补查结果只进待确认，绝不自动入账。已清除的历史通知无法通过此功能读取；原有事件去重避免重复保存。

- 设置 → 查看采集日志：记录微信/支付宝通知的接收、过滤、去重、保存和失败原因，以及服务连接状态。本机最多保留200条，不保存通知正文，不上传服务器；支持刷新与单独清空。日志不等于入账记录；补查仅覆盖通知栏当前仍保留的通知。

- 用户主动授权并开启后，筛选微信、支付宝指定支付服务的系统通知。
- 本地解析金额、商户、付款方式；默认进入待确认。
- 可选自动入账：仅限明确支付成功、唯一金额和唯一付款账户的消费；聚合通知不自动提交。
- 退款、还款、转账、充值等消息只供核对，不能自动按消费提交。
- 消费日期使用通知时间对应的北京时间；旧通知不自动提交。
- 付款账户从自己的归零账本接口读取，不在代码里固定ID。
- 本地 SQLite 保存通知和队列；同一事件查重，近期相同正文标记待核对。
- JobScheduler 在网络可用时上传，断网重试使用同一UUID及相同请求体。
- API Key由 Android Keystore AES-GCM 加密保存；禁止系统备份、HTTP明文和接口重定向。
- 界面包含待确认、记录、设置、纯本地解析演示。

接口已有服务器端幂等保护，但它不能自动识别此前通过聊天手工登记的同一笔支出。试运行期间先使用确认模式，避免重复录入。

## Codemagic 云构建（首选）

### 发布版与应用内更新（0.1.2起）

在 Codemagic 应用的 Environment variables 中添加分组 `guiling_release`，将本机保管的发布凭据文件完整内容填入 `GUILING_RELEASE_BUNDLE_BASE64`，勾选 Secret。不要将凭据提交到 GitHub。此凭据包含固定发布签名和仅能发布 APK 的专用 SSH 密钥，应备份。

选择 main 分支的 **Guiling Android Release + Aliyun** 工作流（`android-release`）。流程依次运行单元测试、Lint、打包、签名校验，然后自动上传到阿里云。测试或校验失败不会上传。每次正式发布须递增 `versionCode`；服务器拒绝重复版本号和回退发布。首次构建成功前，版本地址返回404。

版本地址：`https://tasks.george888.top/guiling-android/latest.json`；APK地址由版本信息指定，例如 `https://tasks.george888.top/guiling-android/guiling-3.apk`。

手机设置 → 检查更新 → 下载更新，下载完成校验SHA256、包名、版本号和现有签名后打开系统安装页面。如需“允许安装未知应用”，授权返回后点击“安装已下载更新”。下载时保持应用打开。此功能不会静默安装，不删除账本，也不会自动卸载旧版本。

之前的调试版可能与固定发布签名不兼容；首次切换应先核对手机未同步记录，安装发布版并重新绑定。后续发布版使用同一签名可覆盖升级。调试工作流不会自动上传。

仓库：https://github.com/epitomizelu/guiling-android

1. 登录 Codemagic，添加此仓库，项目类型选原生 Android / Other，使用仓库根目录的 `codemagic.yaml`。
2. 手动开始构建，分支选 main，工作流选 `android-debug`。
3. 工作流运行单元测试、Lint，生成测试 APK 和设备测试 APK，并校验应用签名。
4. 构建成功后从 Artifacts 下载 `app-debug.apk`。设备测试 APK 仅供后续仪器测试，不作为日常应用安装。

使用 mac_mini_m2 和 Java 17，最长30分钟；不自动触发构建。首次测试无需配置账本密钥或发布签名。当前流程不运行模拟器，真机通知测试仍需在小米14完成。

## GitHub Actions 备用构建

1. 建立一个空的 **私有仓库**。将本目录作为仓库根目录上传，包含 `.github/workflows/android.yml`；不要上传上一级的 debt-manager 或 .android-tools。
2. 默认分支使用 main。仅在需要时进入 Actions → Android APK and tests → Run workflow 手动运行。
3. build任务运行11项JUnit解析测试、Android Lint、打包及APK签名检查。
4. device-tests任务启动Android 15模拟器，测试通知查重、队列请求不可变、Keystore加密往返和启动界面。
5. 两个任务成功后，在Artifacts中下载 `guiling-android-test-apk`，解压得到APK及SHA256校验文件。测试报告单独保留14天。

工作流只调用GitHub托管runner，不使用自己的阿里云服务器。测试不访问生产账本或创建真实交易。费用与额度取决于你的GitHub账号设置；没有自动开通付费服务。

默认产物是已签名的调试测试APK，不是商店发布版。GitHub新runner可能使用不同的调试签名；覆盖安装前需保持签名一致，否则安卓会拒绝更新。正式连续使用前应配置固定发布签名，避免为了更新卸载而丢失本地待处理记录。

## 小米14安装与第一次使用

1. 将APK传到手机，点开安装，按系统提示允许该文件来源安装应用。
2. 打开归零记账助手 → 设置 → 输入API Key。建议在归零手账网页“目标与设置 → 智能体记账接口”新建名为“我的小米14”的独立密钥，只给read、write权限。
3. 点击“打开通知使用权设置”，手动授权“归零支付通知采集”。某些系统需要先在应用信息页允许受限制的设置；入口以手机实际提示为准。
4. 开启“允许采集支付通知”，先保持“明确消费自动入账”关闭。
5. 小米系统中按需允许自启动和后台运行，检查省电设置是否限制本应用。不同HyperOS版本的名称不同。
6. 下一次正常付款后查看待确认列表：核对金额、渠道、账户、日期，再点确认记账。
7. 记录显示“已记账”及服务器编号后，去H5确认余额和收支明细。网络失败时不要另记一笔，先用原队列重试。
8. 分别验证前台、后台、锁屏及重启后的通知接收。确认规则与实际通知匹配后再考虑开启自动模式。

目前尚未采集你手机的真实通知样本，因此预设规则可能只识别部分通知；如果标题、正文格式不同，会忽略或转待确认。微信内部消息没有出现在系统通知栏时无法采集；系统隐藏的内容不能绕过读取。

## 状态与限制

- 待确认：只存手机，没有扣账，可编辑或忽略。
- 待上传：请求内容已锁定，用同一编号重试。不能把这条通知当作未处理再手工登记。
- 已记账：收到并核对服务器成功结果。修改或撤销请到H5进行。
- 提交被拒绝：服务器返回400/403/404/409，保留信息供核对，不自动换编号重记。
- 暂停上传：不再主动提交，已经在途的网络请求仍可能完成。
- 有待上传或被拒绝记录时不能直接换账本/清空，避免响应不确定时重复入账；需先联系维护者核对。
- 本版本不处理自动退款、收入、还款，也不补抓历史账单。

## 本地验证与构建

JDK17、Gradle8.9、Android SDK35、AGP8.7.3。

```text
gradle testDebugUnitTest lintDebug assembleDebug
gradle connectedDebugAndroidTest
```

解析测试可脱离Android运行：编译 `Parser.java` 和 `ParserTest.java`，用JUnit4运行。
设备测试需要模拟器或连接的安卓设备，不能以普通JVM测试代替真实权限验证。

## 隐私

系统“通知使用权”本身范围较广。应用在本地先按包名及支付服务标题过滤，不上传聊天消息、通知原文、银行卡完整信息。仅上传确认后的日期、金额、渠道、账户ID、类别及商户备注。密钥输入对话框禁止截图，其他页面可能包含个人交易内容。

账号密钥不写入APK，不发送给GitHub。删除手机应用会删除本地数据，不会删除服务器账本；重新安装前先处理待提交记录。
